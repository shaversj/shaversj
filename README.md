## Selected Work

### Incident Triage Agent

An SRE-focused agent workflow that turns raw incident signals into an evidence-backed triage result.

What it demonstrates:

- Bounded LLM reasoning
- Evidence packages and provenance
- Local validation and safety gates
- Approval-sensitive action handling
- Scorecards and repeatable scenarios

The design principle is simple: the workflow owns state, validation, evidence, and safety; the LLM owns one bounded judgment.

### Agentic Code Review

I have explored several code review agent architectures, including a GitHub App service and a Flue-based agent workflow.

What it demonstrates:

- Structured review findings
- Severity and confidence calibration
- Deterministic normalization
- Regression evals for drift
- Bounded remediation planning
- Auditable PR publishing

The goal is not generic AI commentary. The goal is consistent, high-signal review output that engineers can trust.

### RAG And Retrieval Evals

The arXiv RAG project is a library-first foundation for retrieval and agent workflows over research papers.

What it demonstrates:

- Hybrid retrieval with vector search and full-text search
- PostgreSQL and pgvector
- Agent-facing retrieval tools
- Observability and tracing
- Retrieval benchmarks and per-query eval artifacts

I am especially interested in evals that diagnose whether a failure came from retrieval, grounding, answer relevance, or answerability.

## How I Think About AI In Engineering

I think about AI in three ways:

1. **Engineering assistant** - useful for code generation, debugging, documentation, architecture exploration, and comparing design approaches.
2. **Workflow accelerator** - useful for reducing friction across planning, code review, research, incident triage, and engineering operations.
3. **Platform capability** - most powerful when teams provide shared agents, retrieval, governance, approval gates, and eval frameworks instead of isolated prompts.

AI should reduce repetitive implementation and coordination work so engineers can spend more time on architecture, product judgment, reliability, and customer problems.

The goal is not to replace engineers. The goal is to increase engineering leverage while keeping humans accountable for correctness, security, and production risk.
